# Курсовой проект «Проектирование автоматизированной системы контроля и обработки багажа авиапассажиров»

Выполнил: Кривов Д. Р., группа ПИ-53, вариант 98.
Языки проекта: **C++** и **Java**.

Проект развивается через лабораторные работы ЛР2–ЛР5: каждая работа — следующий
этап одного и того же приложения по описанию предметной области
(приём, досмотр, сортировка, загрузка и выдача багажа авиапассажиров).

## Структура репозитория

```
cpp/    — реализация на C++ (классы предметной области)
java/   — реализация на Java (package baggage)
report/ — отчёты по работам (pdf)
```

## Сборка и запуск

### C++ (MSVC, x64 Native Tools Command Prompt)

    cl /nologo /EHsc /utf-8 /std:c++17 cpp\*.cpp /Fe:baggage.exe
    baggage.exe

Перед запуском переключите консоль в UTF-8, чтобы русский вывод читался:

    chcp 65001

### C++ (MinGW g++)

    g++ -std=c++17 -Wall cpp\*.cpp -o baggage
    ./baggage

### Java (JDK)

    javac -d out java/src/baggage/*.java
    java -cp out baggage.Main

## ЛР2 — классы, агрегация и композиция (ветка lab-02)

Классы (папка `cpp/`):

| Класс | Файлы | Связь | Ответственность |
|---|---|---|---|
| `BaggageTag` | `baggage_tag.hpp/.cpp` | — | багажная бирка: уникальный номер, дата оформления, сверка с отрывной частью (правило 2: номер не пуст) |
| `BaggagePiece` | `baggage_piece.hpp/.cpp` | **композиция** с биркой (поле-объект, живёт и умирает с местом) | место багажа: вес, габариты, статус; приём на стойке (правило 4: не более 32 кг), смена статуса только вперёд (правило 12) |
| `Flight` | `flight.hpp/.cpp` | **агрегация** мест (манифест хранит указатели, местами не владеет) | рейс: номер, аэропорты, вместимость; назначение мест (правило 7: мест и суммарный вес не больше вместимости отсека), закрытие регистрации (правило 9) |

(место переживает уничтоженный рейс), работа по ссылке и по указателю,
`new`/`delete`, динамический массив объектов и массив динамических объектов.

## ЛР3 ч.2 — умные указатели C++ (ветка lab-03-cpp)

Начиная с этой работы в C++-проекте используются только умные указатели;
`new`/`delete` в коде нет.

| Где | Владение | Почему |
|---|---|---|
| места багажа в `main` | `std::shared_ptr<BaggagePiece>` (`make_shared`) | единый владелец — стойка/пассажир; при выдаче место передаётся по общему владению |
| манифест рейса (`Flight`) | `std::vector<std::weak_ptr<BaggagePiece>>` | агрегация: рейс местами не владеет, перед использованием — `lock()` с проверкой |
| короткоживущие места | `std::unique_ptr<BaggagePiece>` (`make_unique`) | владелец один; уничтожение при выходе из блока; передача владения через `std::move` |
| массивы | `std::vector<BaggagePiece>` и `std::vector<std::unique_ptr<BaggagePiece>>` | вместо `new[]`/`delete[]` |
| бирка в месте | поле-объект по значению (не менялось с ЛР2) | композиция — самый надёжный вид владения |

Демонстрация (`cpp/main.cpp`): те же проверки правил, что и в ЛР2, плюс
`use_count()` при копировании/уничтожении `shared_ptr`, `std::move` с пустым
исходным указателем, `lock()` по живому и уничтоженному месту.

Эталонный вывод C++-программы — `console_output.txt`.

## ЛР4 — наследование C++ (ветка lab-04-cpp)

Иерархия (папка `cpp/`): `BaseBaggage` (абстрактный) → `StandardBaggage`,
`OversizeBaggage`, `FragileBaggage` (final); норма провоза — `BaggageNorm`,
спецификация негабарита — `EquipmentSpec`.

| Элемент | Где | Как демонстрируется |
|---|---|---|
| абстрактный класс | `BaseBaggage` | чисто виртуальные `ExcessFee()` и `Clone()`; создание объекта невозможно |
| protected | поля `m_tag`, `m_weightKg`, `m_dimsSumCm`, `m_status`, доступ наследников | наследники используют в `ExcessFee`/`Describe`, наружу не отдаются |
| конструкторы | база → наследник в списке инициализации | по выводу: сначала `[Базовый]`, затем наследник |
| виртуальный деструктор | `virtual ~BaseBaggage` | уничтожение через `unique_ptr<BaseBaggage>`: деструктор наследника, затем базы |
| поверхностная копия | `StandardBaggage` (правило нуля) | копия делит `shared_ptr<BaggageTag>`: номера бирок совпадают, правило 2 нарушено |
| глубокая копия | `OversizeBaggage` (правило пяти: copy/move/assign) + виртуальный `Clone()` | у копии новая бирка (генератор номеров) и собственная спецификация |
| переопределение | `StandardBaggage::Describe()` вызывает `BaseBaggage::Describe()`, остальные — без | дополнение vs замена |
| final | `FragileBaggage final` | запрет наследования хрупкого места |
| строки | `Flight::ParseNumber` | `find`, `substr`, сравнение, конкатенация на номере рейса |
| this | `OversizeBaggage::operator=` | защита самоприсваивания, возврат `*this` |
| статические члены | `BaggageTag::GenerateNumber()` | статический счётчик, уникальные номера бирок (правило 2) |
| демонстрация | `cpp/main.cpp` | массив `unique_ptr<BaseBaggage>`, приёмка через базовый указатель, полиморфные сборы |

## ЛР5 — полиморфизм C++ (ветка lab-05-cpp)

| Элемент | Где | Как демонстрируется |
|---|---|---|
| интерфейс `IScannable` (только чисто виртуальные + virtual dtor) | `is_scannable.hpp` | контракт «место можно просканировать по штрих-коду» |
| реализация интерфейса двумя классами | `StandardBaggage`, `OversizeBaggage` | оба умеют `ScanBarcode()` |
| множественное наследование | `OversizeBaggage : BaseBaggage, IScannable` | абстрактный класс из ЛР4 + интерфейс |
| работа через интерфейс | `SortingSystem::RouteToLoading` | не знает конкретных классов, только `IScannable` |
| `dynamic_cast` | `SortingSystem` | только реализующие `IScannable` места уходят на загрузку, `FragileBaggage` — на ручную обработку |
| раннее/позднее связывание | секция 3 вывода | невиртуальный `GetWeightKg()` vs виртуальный `Describe()` через `BaseBaggage&` |
| динамическое конфигурирование | `CheckInDesk` + `IFeePolicy` | стойка хранит `unique_ptr<IFeePolicy>`, `SetFeePolicy()` меняет сбор на ходу: 1500 → 750 → 2500 руб. |
| исключения | `baggage_rule_error.hpp` | `BaggageRuleError : std::logic_error` + `OverweightError`, `FlightCapacityError`, `NotClearedError`, `CheckinClosedError`, `NotOnRouteError`, `DuplicateTagError` |
| try/catch | `main.cpp` | от частного к общему, перехват по `const&`, видно успех и перехват; без `catch (...)` |
| noexcept | деструкторы и move-операции | помечены явно |

Сборка: `cl /nologo /EHsc /utf-8 /std:c++17 cpp\*.cpp /Fe:baggage.exe`, запуск: `chcp 65001`, `baggage.exe`.
